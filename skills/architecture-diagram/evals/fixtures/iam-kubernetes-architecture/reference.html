Proposed Kubernetes IAM deployment

A vendor-neutral server topology for a Spring Boot IAM service and its audit worker. It shows logical request and dependency paths, not observed configuration, physical worker placement, or a high-availability guarantee.

Logical grouping

The dashed namespaces group Kubernetes objects for readability. A namespace does not by itself provide network isolation, and the pod groups do not map to physical workers.

State placement

This proposal places PostgreSQL, Redis, and RabbitMQ outside the cluster on a private network. PostgreSQL stores IAM state and append-only audit records; separate schemas or databases remain an implementation choice.

Scope

Responses, health checks, autoscaling, backups, secret delivery, encryption keys, and network policies are omitted. Secret and key management still require an explicit design.
